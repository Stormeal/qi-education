## Delivered behavior

One private working revision coexists with the live course. Owners/admins start
and edit drafts, submit a frozen snapshot, and see chronological history. Admins
return with a required reason or publish the reviewed snapshot. Publication writes
live metadata, lessons, thumbnail pointer and decision history together. Existing
learners continue on the live course throughout editing, review and return.

All actors create drafts. General creation/metadata/content/media paths cannot
bypass review. Existing owner boundaries and admin-only price/catalog controls
remain. Archive is explicit, retains enrolled access and preserves unsaved working
buffers. A read-only submitted preview exposes text, questions/correct answers,
media and resource downloads to authorized reviewers.

## Implementation decisions and limits

- Workflow lives in the existing Mongo content document: publication remains one
  provider write instead of coordinating Sheet and content switches. Sheets keep
  identity/owner and admin price/catalog authority; reviewed author fields are
  composed from snapshots. Cost: catalog reads also fetch content documents; the
  separate capacity investigation remains Proposed.
- Legacy initialization is lazy. A first legacy draft edit retains its original
  provider write then materializes the workflow before success; subsequent writes
  use snapshots. Failure follows existing uncertain-write coordination. Cost:
  initial legacy edits can involve more than one provider write; hosted recovery
  still needs isolated integration verification.
- Review-action version checks protect decisions, not all concurrent author saves.
  General stale-editor behavior stays US-T005; broader media operations stay US-T006.
- Full history is never silently shortened. Mongo document limits remain real;
  oversized/uncertain writes fail safely instead of claiming publication. History
  pagination/external event storage is not included.
