## Regression evidence

Before the fix, the new API suite had 20 failures out of 29 tests: ownership was
missing and unrelated teachers could reach authoring handlers. The corrected UI
regression run had four failures: unrelated teacher entry, teacher/student direct
editor URLs, and drafts filtered by instructor name. These failures preceded the
corresponding implementation changes.

Independent review found that a forged foreign asset reference on an owned course
could reach asset deletion. Eight API and two repository regressions failed before
the additional fix, then passed. They cover creation thumbnail assignment, content
attachment assignment, attachment deletion through an existing bad reference,
thumbnail cleanup preserving foreign images, and course-scoped memory/Mongo deletion.

`api/src/courseOwnership.test.ts` covers creation from authenticated identity,
ignored forged owner assignment, immutable ownership during edits, old 20-column
rows, current Sheets row roundtrip, same-name teachers, all seven authoring routes
with both standard and `/api` paths, and owner/admin successes. Denial tests assert
unchanged metadata/content and no asset, content, metadata, or Mux writes.
Authentication tests cover anonymous, student, disabled-user, and missing-course
requests. External Mux upload creation uses a test double; no real media is sent.

The independent reviewer inspected the correction and reran all 44 ownership/asset
tests successfully, finding no remaining Critical or Important ownership issue.
Future coverage can add content-only denied-save retention and mocked Sheets
repository request checks. Those suggestions do not replace live release checks.

`app/src/app/services/course-ownership.spec.ts` verifies blocked editor entry,
direct denied routes without editable controls, owner/admin access, and retention
of local metadata edits after a forbidden API response. The catalog regression in
`courses-page.spec.ts` verifies ID-based draft filtering and admin access to all drafts.
